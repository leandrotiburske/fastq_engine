# fastq_engine

Processing engine for the full-stack application
[leandrotiburske/variant_platform](https://github.com/leandrotiburske/variant_platform).

This service receives FASTQ analysis requests, creates asynchronous processing
tasks, runs the `nf-core/sarek` pipeline with Nextflow, and sends the called
variants back to the main platform, where clinicians can review, classify, and
submit genetic variant analyses for their patients.

## What This Engine Does

- Exposes an HTTP API with FastAPI for task submission and task lookup.
- Creates one `samplesheet` per analysis using patient metadata and FASTQ paths.
- Queues long-running jobs with Celery and RabbitMQ.
- Runs `nf-core/sarek` through Nextflow inside the worker container.
- Persists task status, output directories, return codes, and timestamps in PostgreSQL.
- Reads the final VCF generated by the pipeline and posts variants to `variant_platform`.
- Links the created variants to the corresponding patient in the main platform.

## Tech Stack

| Layer | Technology |
| --- | --- |
| API | FastAPI + Uvicorn |
| Queue | Celery |
| Broker | RabbitMQ |
| Queue monitoring | Flower |
| Database | PostgreSQL + SQLAlchemy |
| Pipeline | Nextflow + `nf-core/sarek` |
| Runtime | Docker Compose |

## Running With Docker

### 1. Create a `.env` file

```env
USERNAME=guest
PASSWORD=guest

POSTGRES_USER=fastq
POSTGRES_PASSWORD=fastq
POSTGRES_DB=fastq_engine
POSTGRES_HOST=db
```

> When running with Docker Compose, `POSTGRES_HOST` should point to the `db`
> service.

### 2. Start the stack

```bash
docker compose up --build
```

The first build can take a while because the image installs Java, Nextflow,
Python dependencies, and pulls `nf-core/sarek`.

### 3. Open the services

| Service | URL |
| --- | --- |
| API | http://localhost:8000 |
| Swagger/OpenAPI | http://localhost:8000/docs |
| Healthcheck | http://localhost:8000/health |
| Flower | http://localhost:5556 |
| RabbitMQ Management | http://localhost:15672 |
| PostgreSQL | localhost:5434 |

## Integration With `variant_platform`

The worker sends called variants to the main platform backend through:

```text
POST  http://host.docker.internal:8080/variants
PATCH http://host.docker.internal:8080/subjects/{patient_id}/add_variants
```

For the full local workflow to work, keep the `variant_platform` backend running
on the host machine at port `8080`.

The API is also configured with CORS for the frontend at:

```text
http://localhost:5173
```

## API Endpoints

### `GET /health`

Checks whether the API is running.

```json
{
  "message": "OK"
}
```

### `POST /submit_task`

Submits a new FASTQ analysis. The current implementation receives all fields as
query parameters.

| Parameter | Type | Description |
| --- | --- | --- |
| `patient_name` | string | Patient/sample name used in the samplesheet |
| `patient_id` | int | Patient ID in `variant_platform` |
| `sex` | string | Sex value passed to the pipeline |
| `fastq1` | string | FASTQ R1 path visible inside the container |
| `fastq2` | string | FASTQ R2 path visible inside the container |

Example:

```bash
curl -G -X POST "http://localhost:8000/submit_task" \
  --data-urlencode "patient_name=patient_demo" \
  --data-urlencode "patient_id=1" \
  --data-urlencode "sex=XX" \
  --data-urlencode "fastq1=/app/fastqs/test_1.fastq.gz" \
  --data-urlencode "fastq2=/app/fastqs/test_2.fastq.gz"
```

Expected response:

```json
{
  "id": 1,
  "patient_id": 1,
  "status": "PENDING",
  "samplesheet_path": "/app/samplesheets/20260402_101208/samplesheet_20260402_101208.csv"
}
```

### `GET /get_all_tasks`

Lists all registered tasks.

### `GET /get_task/{task_id}`

Returns one task by ID.

### `GET /get_patient_tasks/{patient_id}`

Lists all tasks for a patient.

## Task Lifecycle

| Status | Meaning |
| --- | --- |
| `PENDING` | Task was created and is waiting to be processed |
| `RUNNING` | Worker started the Nextflow execution |
| `SUCCESS` | Pipeline finished with return code `0` |
| `FAILURE` | Pipeline execution or platform integration failed |

During execution, the worker also stores:

- `celery_task_id`
- `started_at`, `updated_at`, `completed_at`
- `workdir`
- `outdir`
- `return_code`

## Generated Files

| Path | Contents |
| --- | --- |
| `samplesheets/` | Samplesheets generated for each submission |
| `test/{task_id}/` | Pipeline outputs plus `stdout.log` and `stderr.log` |
| `work/` | Nextflow work directory |
| `.nextflow/` | Nextflow cache and metadata |
| `fastqs/` | Local FASTQs used for development/testing |

These directories are listed in `.gitignore` or `.dockerignore` because they can
contain large, temporary, or sensitive files.
